# CPU

## CPUにできること
CPUにできることは様々な命令を持ち、

- 加算
- 減算
- 比較
- ジャンプ
を組み合わせて作られます。

他にも
- 論理演算(AND/OR/XOR)
- シフト
- メモリ書き込み
などがあります。

## レジスタ
何となく聞いたことがありましたが、
これはCPUの中にある超高速なメモリです。

メモリでもRAMの方はCPUもより巨大である反面、速度は低速です。
アセンブラで、
```asm
rax
rbx
rcx
rdx
```
というよう表現をするようです。

そのような事もあり、CPUはRAMから直接計算するのは苦手だそうです。

つまりCPUはレジスタ同士の計算は高速ですが、
RAMへのアクセスは比較的遅いため、できるだけレジスタを使いまわそうとします。

そしてCPUは
```
メモリ
↓
レジスタ
↓
演算
```
のような動きます。

Rustで
```rust
fn main() {
    let a = 5;
    let b = 3;
    
    let c = a + b;
}
```
のようなコードがあった場合、

アセンブラでは
```asm
mov rax, 5
mov rbx, 3

add rax,rbx
```
のような書き方で、
```
rax = 8
```
となり、同時に
```
rax = c
```
となることもあります。

これはあくまで変数は人からみて分かり易くなっているだけで
raxはメモリではなくレジスタなので、CPU内部では既に`rax = 8`になっていて、
計算結果はレジスタに保持されているため、
態々別のレジスタへ移す必要がない場合もあるからです。

その為、実際にどのレジスタを使うか、別のレジスタへ移すか、
スタックへ保存するかはコンパイラや最適化の状況次第です。

例えば必要があれば、

```asm
mov rcx, rax
```
のように別のレジスタへ移すこともあります。

ここで重要なのはCPUは多くの場合、レジスタに値を置いて演算する
```
rax + rbx
```
とレジスタを見て計算をすることです。

---

ではレジスタはどのくらいあるのかというと、
そこまで多くないようで、
x86-64なら
```asm
RAX
RBX
RCX
RDX
RSI
RDI
RSP
RBP
```
が代表的なレジスタだそうです。
他にも
```asm
R8
R9
R10
R11
R12
R13
R14
R15
```
のようなレジスタもあります。

数が少ないためコンパイラはどの変数をどのレジスタに
置くのか慎重に考えています。

このコンパイラの処理を
**レジスタ割り当て(Register Allocation)**
と呼びます

---

Rustでは
```rust
fn main() {
    let a = 5;
}
```
というコードがあった場合、
- レジスタ
- スタック
- ヒープ
のいずれかに置かれます。

Rustの教本などでは
- スタック
- ヒープ
と説明されていることがほとんどですが、

直接レジスタに置かれる事もあるそうです。
これは常になるわけではなく、コンパイラ次第のようです。
この挙動を
**最適化**
と言います。

私もスタックやヒープかと思っていたので驚きました。

そしてコンパイラは賢くて、
```rust
fn main() {
    let x = 10 + 20;
    println!("{}", 30 + 40);
}
```
のような処理を
```rust
fn main() {
    let x = 30;
    println!("{}", 70);
}
```
のような計算できるものは計算した後の形に変えてしまいます。
これを
**定数畳み込み(Constant Folding)**
と呼びます。

---

レジスタには特殊な役割のあるレジスタがあります。
それが`RSP`と`RIP`で、

`RSP`はスタックポインタといい、今のスタックの先頭を指します。

`RIP`は命令ポインタといい、次に実行する命令の場所を指します。

例えば
```rust
fn main() {
    foo();
}

fn foo() {
    ...
}
```
を実行すると、`main関数`から`foo関数`の呼び出し処理をCPUは
```
RIP
↓
fooのアドレスへ変更
↓
関数へ飛ぶ
```
という動きをします。
